Lập trình thi đấu gồm hai phần: thiết kế thuật toán (nghĩ ra cách giải vừa đúng vừa đủ nhanh) và cài đặt thuật toán (viết mã chạy đúng trên mọi bộ kiểm thử). Chương này gom những thứ nền tảng nhất về C++ và toán mà các chương sau sẽ dùng lại liên tục.

1.Khung chương trình C++

Một khung mã C++ điển hình cho thi đấu:

#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(0);
    cin.tie(0);
    // lời giải của bạn ở đây
    return 0;
}

Dòng #include <bits/stdc++.h> nạp toàn bộ thư viện chuẩn, khỏi khai báo lẻ từng thứ. Dòng using namespace std; cho phép viết cout thay vì std::cout. Hai dòng đầu main tăng tốc nhập/xuất. Biên dịch:

g++ -std=c++14 -O2 -Wall test.cpp -o test

2.Nhập và xuất dữ liệu

Dùng cin để đọc, cout để in. Các giá trị cách nhau bởi dấu cách hoặc xuống dòng đều đọc được:

int a, b; string x;
cin >> a >> b >> x;
cout << a << " " << b << " " << x << "\n";
Vài mẹo nhập/xuất
  • Dùng "\n" thay endl: endl còn đẩy bộ đệm nên chậm hơn.
  • Đọc trọn một dòng (kể cả dấu cách): getline(cin, s);
  • Đọc đến hết dữ liệu khi không biết trước số lượng: while (cin >> x) { ... }

3.Làm việc với số

Số nguyên. int là 32-bit, chứa cỡ −2·109 … 2·109. Không đủ thì dùng long long (64-bit), chứa cỡ −9·1018 … 9·1018.

Bẫy tràn số hay gặp nhất
Khai báo kết quả là long long vẫn chưa đủ: nếu hai thừa số đều là int thì phép nhân được tính bằng int rồi mới gán, nên đã tràn trước khi kịp thành long long. Bấm thử:
int a = 123456789;
long long b = a * a;  // mong đợi 15241578750190521

Số học phần dư. Khi đề yêu cầu in đáp số “theo modulo m” (phần dư khi chia cho m, thường m = 109+7), ta lấy dư sau mỗi phép cộng, trừ, nhân để số không bao giờ quá lớn:

long long x = 1;
for (int i = 2; i <= n; i++) x = (x * i) % m;   // n! mod m
cout << x % m << "\n";

Vì x luôn < m ≤ 109 và i nhỏ, tích x*i nằm gọn trong long long. Nếu có phép trừ, phần dư có thể âm — sửa bằng x %= m; if (x < 0) x += m;

Số thực. double (64-bit) thường đủ; muốn chính xác hơn dùng long double. Số thực có sai số làm tròn, nên đừng so sánh bằng ==:

double x = 0.3*3 + 0.1;   // 0.99999999999999988898, KHÔNG đúng bằng 1
if (abs(a - b) < 1e-9) { /* coi như bằng nhau */ }

4.Rút gọn mã

Đặt tên ngắn cho kiểu hay dùng bằng typedef, và thay cụm dài bằng #define để gõ nhanh hơn:

typedef long long ll;
typedef pair<int,int> pii;
#define pb push_back
#define REP(i,a,b) for (int i = a; i <= b; i++)
Bẫy macro thiếu ngoặc
#define SQ(a) a*a khiến SQ(3+3) bung thành 3+3*3+3 = 15, không phải 36. Luôn bọc ngoặc: #define SQ(a) (a)*(a).

5.Một ít công thức toán

Những công thức tổng và logarit dưới đây sẽ dùng liên tục khi ước lượng độ phức tạp:

Công thức hay dùng
  • Tổng 1 + 2 + … + n = n(n+1)/2.
  • Tổng bình phương 12 + 22 + … + n2 = n(n+1)(2n+1)/6.
  • Cấp số nhân đôi 1 + 2 + 4 + … + 2n−1 = 2n − 1.
  • Tổng điều hòa 1 + 1/2 + … + 1/n ≤ log2 n + 1.

Logarit logk x chính là số lần chia x cho k đến khi còn 1. Ví dụ log2 32 = 5 vì

32 -> 16 -> 8 -> 4 -> 2 -> 1   (chia 2 đúng 5 lần)

Vì nhiều thuật toán hiệu quả chia đôi dữ liệu mỗi bước nên logarit xuất hiện khắp nơi trong phân tích độ phức tạp (xem chương Độ phức tạp thời gian).
