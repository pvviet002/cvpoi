1Bài toán mở đầu: tô một vùng kín

Trong các phần mềm vẽ, công cụ thùng sơn cho phép nhấp vào một điểm và tô toàn bộ vùng có cùng màu với điểm đó. Màu mới lan sang các ô kề, rồi tiếp tục lan từ những ô vừa tô, cho đến khi gặp đường biên hoặc một màu khác.

Trong lập trình thi đấu, quá trình này được gọi là loang hay Flood Fill. Kỹ thuật này không chỉ dùng để tô màu, mà còn để đếm đảo, tìm vùng nước, đo diện tích miền, kiểm tra đường đi trong mê cung, xác định vùng bao quanh và xử lý rất nhiều bài toán trên ma trận.

Ý tưởng cốt lõi

Mỗi ô hợp lệ được xem như một đỉnh. Hai ô có thể chuyển trực tiếp cho nhau được nối bằng một cạnh. Flood Fill thực chất là một lần duyệt DFS hoặc BFS trên đồ thị ẩn này.

2Mô hình hoá lưới thành đồ thị

2.1. Ô, cạnh và điều kiện hợp lệ

Cho ma trận gồm n hàng và m cột. Ô tại hàng i, cột j được ký hiệu là (i, j). Khi duyệt, một ô chỉ được đưa vào vùng loang nếu đồng thời thoả mãn:

  • Nằm trong biên của ma trận.
  • Thoả điều kiện của đề bài, chẳng hạn là đất, là ô trống hoặc có cùng màu với ô nguồn.
  • Chưa được thăm trước đó.

2.2. Bốn hướng và tám hướng

Hai ô chạm nhau ở một góc có thuộc cùng vùng hay không phụ thuộc hoàn toàn vào đề bài. Chọn nhầm 4 hướng thành 8 hướng hoặc ngược lại sẽ làm thay đổi số thành phần liên thông.

3Nguyên lý của thuật toán loang

Mô tả thuật toán
  1. Chọn ô bắt đầu (sx, sy).
  2. Đánh dấu ô đó đã được thăm.
  3. Xét mọi ô kề theo quy tắc 4 hoặc 8 hướng.
  4. Với mỗi ô kề hợp lệ và chưa thăm, đánh dấu rồi tiếp tục loang từ ô đó.
  5. Dừng khi không còn ô nào chờ xử lý.

3.1. Bất biến quan trọng

Mỗi ô được đưa vào cấu trúc duyệt nhiều nhất một lần. Vì vậy, dù từ một ô ta thử nhiều hướng, tổng số thao tác vẫn tuyến tính theo số ô của ma trận.

3.2. Chứng minh đúng

Tính không bỏ sót. Nếu một ô v thuộc cùng vùng với ô nguồn, tồn tại một dãy các ô kề hợp lệ từ nguồn tới v. Thuật toán lần lượt mở rộng qua từng cạnh trên dãy đó, nên cuối cùng sẽ thăm v.

Tính không thăm thừa. Thuật toán chỉ chuyển sang ô kề khi ô đó thoả điều kiện hợp lệ, vì thế không thể vượt qua tường hay đi vào một vùng khác.

3.3. Độ phức tạp

Đánh giá
  • Thời gian: O(n · m) trong trường hợp duyệt toàn bộ lưới.
  • Bộ nhớ: O(n · m) cho mảng đánh dấu và ngăn xếp hoặc hàng đợi.
  • Nếu chỉ loang một vùng có S ô, chi phí thực tế là O(S).

4Cài đặt bằng DFS và BFS

4.1. DFS đệ quy

DFS đi sâu theo một nhánh trước, sau đó quay lui. Đây là cách viết ngắn và gần với định nghĩa loang nhất.

Flood Fill bằng DFS đệ quy
#include <bits/stdc++.h>
using namespace std;

const int MAXN = 1005;
int n, m, a[MAXN][MAXN];
bool visited[MAXN][MAXN];
int dx[4] = {-1, 1, 0, 0};
int dy[4] = {0, 0, -1, 1};

bool inside(int x, int y) {
    return 1 <= x && x <= n && 1 <= y && y <= m;
}

void dfs(int x, int y) {
    visited[x][y] = true;
    for (int k = 0; k < 4; k++) {
        int nx = x + dx[k];
        int ny = y + dy[k];
        if (inside(nx, ny) && a[nx][ny] == 1 && !visited[nx][ny])
            dfs(nx, ny);
    }
}
Nguy cơ tràn ngăn xếp

Nếu vùng liên thông có hàng trăm nghìn hoặc hàng triệu ô, độ sâu đệ quy có thể rất lớn. Khi giới hạn lưới lớn, nên dùng BFS hoặc DFS khử đệ quy.

4.2. BFS bằng hàng đợi

BFS mở rộng theo từng lớp khoảng cách. Cách này an toàn với vùng lớn và còn cho phép tính đường đi ngắn nhất trên lưới không trọng số.

Flood Fill bằng BFS
void bfs(int sx, int sy) {
    queue<pair<int, int>> q;
    q.push({sx, sy});
    visited[sx][sy] = true; // đánh dấu ngay khi đưa vào hàng đợi

    while (!q.empty()) {
        auto [x, y] = q.front();
        q.pop();

        for (int k = 0; k < 4; k++) {
            int nx = x + dx[k];
            int ny = y + dy[k];
            if (inside(nx, ny) && a[nx][ny] == 1 && !visited[nx][ny]) {
                visited[nx][ny] = true;
                q.push({nx, ny});
            }
        }
    }
}

void floodFillStack(int sx, int sy) {
    stack<pair<int, int>> st;
    st.push({sx, sy});
    visited[sx][sy] = true;

    while (!st.empty()) {
        auto [x, y] = st.top();

            if (inside(nx, ny) && a[nx][ny] == 1 && !visited[nx][ny]) {
                visited[nx][ny] = true;
                st.push({nx, ny});
            }
        }
    }
}

5Đếm thành phần liên thông

Một trong những mẫu bài quan trọng nhất là đếm số vùng tách biệt. Ta duyệt toàn bộ ma trận; mỗi khi gặp một ô hợp lệ chưa thăm, đó là điểm bắt đầu của một thành phần mới. Tăng đáp án lên 1 rồi loang để đánh dấu toàn bộ thành phần đó.

Đếm số vùng gồm các ô giá trị 1
int components = 0;
for (int i = 1; i <= n; i++) {
    for (int j = 1; j <= m; j++) {
        if (a[i][j] == 1 && !visited[i][j]) {
            components++;
            bfs(i, j);
        }
    }
}
cout << components << '\n';

5.1. Thu thập thông tin của từng vùng

Trong lúc loang, ta có thể tính đồng thời nhiều đại lượng:

  • Diện tích: tăng 1 khi thăm một ô.
  • Chu vi: với mỗi cạnh của ô đang xét, nếu phía bên kia ra ngoài lưới hoặc là ô nước thì tăng 1.
  • Hộp bao: cập nhật hàng nhỏ nhất, lớn nhất, cột nhỏ nhất, lớn nhất.
  • Khoảng cách: BFS lưu dist[nx][ny] = dist[x][y] + 1.
  • Ô đại diện: lưu ô đầu tiên hoặc ô có thứ tự từ điển nhỏ nhất.

5.2. Tính diện tích và chu vi

Loang một đảo và tính đồng thời diện tích, chu vi
pair<int, int> measure(int sx, int sy) {
    queue<pair<int, int>> q;
    q.push({sx, sy});
    visited[sx][sy] = true;
    int area = 0, perimeter = 0;

    while (!q.empty()) {
        auto [x, y] = q.front(); q.pop();
        area++;
        for (int k = 0; k < 4; k++) {
            int nx = x + dx[k], ny = y + dy[k];
            if (!inside(nx, ny) || a[nx][ny] == 0) {
                perimeter++;
            } else if (!visited[nx][ny]) {
                visited[nx][ny] = true;
                q.push({nx, ny});
            }
        }
    }
    return {area, perimeter};
}

6Những lỗi thường gặp

Danh sách kiểm tra trước khi nộp bài
  1. Quên kiểm tra biên trước khi truy cập ma trận.
  2. Đánh dấu quá muộn. Với BFS, phải đánh dấu ngay lúc đưa ô vào hàng đợi; nếu chờ đến lúc lấy ra, một ô có thể bị thêm nhiều lần.
  3. Nhầm 4 hướng và 8 hướng.
  4. Đổi màu nguồn quá sớm nhưng lại tiếp tục so sánh với màu hiện tại thay vì lưu màu ban đầu.
  5. Không xử lý trường hợp màu mới bằng màu cũ. Một số cài đặt thay màu trực tiếp sẽ lặp vô hạn nếu không kiểm tra.
  6. DFS đệ quy quá sâu gây Runtime Error.
  7. Dùng chung mảng visited cho nhiều test mà không xoá.
  8. Sai chỉ số 0/1-based giữa dữ liệu và hàm kiểm tra biên.
  9. Loang nhầm điều kiện. Có bài yêu cầu cùng ký tự, có bài chỉ cần khác tường, có bài còn ràng buộc độ cao.

6.1. Flood Fill đổi màu

Đổi toàn bộ vùng cùng màu với ô nguồn
void recolor(int sx, int sy, int newColor) {
    int oldColor = a[sx][sy];
    if (oldColor == newColor) return;

    queue<pair<int, int>> q;
    q.push({sx, sy});
    a[sx][sy] = newColor;

    while (!q.empty()) {
        auto [x, y] = q.front(); q.pop();
        for (int k = 0; k < 4; k++) {
            int nx = x + dx[k], ny = y + dy[k];
            if (inside(nx, ny) && a[nx][ny] == oldColor) {
                a[nx][ny] = newColor;
                q.push({nx, ny});
            }
        }
    }
}

7Ứng dụng và các biến thể

7.1. Bài toán đếm đảo

Mỗi ô đất là một đỉnh; hai ô đất kề nhau được nối cạnh. Số đảo chính là số thành phần liên thông của đồ thị ô đất.

7.2. Mê cung và đường đi ngắn nhất

Khi mỗi bước có cùng chi phí, BFS từ ô xuất phát cho khoảng cách ngắn nhất tới mọi ô có thể tới. Có thể lưu thêm mảng cha để dựng lại đường đi.

7.3. Loang đa nguồn

Đưa tất cả nguồn vào hàng đợi ở khoảng cách 0 trước khi BFS. Kỹ thuật này dùng trong bài cháy lan, lây nhiễm, khoảng cách tới bệnh viện gần nhất hoặc biến đổi ma trận.

BFS đa nguồn
queue<pair<int, int>> q;
for (auto [x, y] : sources) {
    dist[x][y] = 0;
    q.push({x, y});
}
while (!q.empty()) {
    auto [x, y] = q.front(); q.pop();
    for (int k = 0; k < 4; k++) {
        int nx = x + dx[k], ny = y + dy[k];
        if (inside(nx, ny) && dist[nx][ny] == -1) {
            dist[nx][ny] = dist[x][y] + 1;
            q.push({nx, ny});
        }
    }
}

7.4. Loang theo độ cao hoặc điều kiện động

Cạnh giữa hai ô chỉ tồn tại nếu thoả điều kiện như |h[u] - h[v]| ≤ K, ô sau không thấp hơn ô trước, hoặc thời điểm tới ô phải sớm hơn lửa. Flood Fill không thay đổi; chỉ thay hàm kiểm tra chuyển trạng thái.

7.5. Đánh dấu vùng ngoài

Thay vì loang từ một ô bên trong, ta thêm các ô biên hợp lệ làm nguồn và loang từ ngoài vào. Những ô không được thăm sau đó chính là vùng bị bao kín. Đây là cách giải điển hình cho bài “Surrounded Regions”.

7.6. Nén thành phần

Sau khi gán nhãn mỗi vùng bằng một mã thành phần, ta có thể coi cả vùng như một đỉnh mới. Các quan hệ giữa vùng tạo thành một đồ thị nhỏ hơn, giúp giải các bài nhiều tầng.

7.7. Lưới không đều và đồ thị tổng quát

Flood Fill không bắt buộc phải chạy trên ma trận. Trên đồ thị danh sách kề, thao tác tương tự chính là DFS/BFS tìm thành phần liên thông.

8Bài tập mẫu có lời giải

8.1. Bài 1 — Đếm số đảo

Đề. Cho ma trận n × m gồm ký tự '.' và '#'. Hai ô '#' thuộc cùng đảo nếu kề cạnh. Hãy đếm số đảo.

Phân tích. Duyệt mọi ô; khi gặp đất chưa thăm, tăng số đảo và BFS toàn bộ vùng đó.

Lời giải hoàn chỉnh
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m;
    cin >> n >> m;
    vector<string> a(n);
    for (string &row : a) cin >> row;

    vector<vector<bool>> vis(n, vector<bool>(m, false));
    int dx[4] = {-1, 1, 0, 0};
    int dy[4] = {0, 0, -1, 1};
    int islands = 0;

    for (int i = 0; i < n; i++) {
        for (int j = 0; j < m; j++) {
            if (a[i][j] != '#' || vis[i][j]) continue;
            islands++;
            queue<pair<int, int>> q;
            q.push({i, j});
            vis[i][j] = true;

            while (!q.empty()) {
                auto [x, y] = q.front(); q.pop();
                for (int k = 0; k < 4; k++) {
                    int nx = x + dx[k], ny = y + dy[k];
                    if (0 <= nx && nx < n && 0 <= ny && ny < m &&
                        a[nx][ny] == '#' && !vis[nx][ny]) {
                        vis[nx][ny] = true;
                        q.push({nx, ny});
                    }
                }
            }
        }
    }
    cout << islands << '\n';
}

8.2. Bài 2 — Diện tích vùng lớn nhất

Đề. Cho ma trận nhị phân. Hãy tìm số ô lớn nhất trong một thành phần 4 hướng gồm toàn số 1.

Phân tích. Mỗi lần bắt đầu một vùng mới, đặt area = 0, tăng khi lấy một ô ra khỏi hàng đợi, rồi cập nhật đáp án lớn nhất.

Hàm tính diện tích một vùng
int getArea(int sx, int sy) {
    queue<pair<int, int>> q;
    q.push({sx, sy});
    visited[sx][sy] = true;
    int area = 0;
    while (!q.empty()) {
        auto [x, y] = q.front(); q.pop();
        area++;
        for (int k = 0; k < 4; k++) {
            int nx = x + dx[k], ny = y + dy[k];
            if (inside(nx, ny) && a[nx][ny] == 1 && !visited[nx][ny]) {
                visited[nx][ny] = true;
                q.push({nx, ny});
            }
        }
    }
    return area;
}

Đề. Tìm số bước ít nhất từ S tới T, chỉ đi qua ô không phải tường.

8.4. Bài 4 — Vùng bị bao quanh

Đề. Trên bảng gồm O và X, đổi mọi vùng O bị bao kín bởi X thành X.

Phân tích. Các ô O nối được với biên không bị bao kín. Loang từ mọi ô O trên biên để đánh dấu an toàn; cuối cùng đổi những ô O chưa đánh dấu.

10Tổng kết

Năm câu hỏi cần trả lời khi gặp bài loang
  1. Trạng thái là gì? Thường là một ô, nhưng có thể kèm hướng, chìa khoá hoặc thời gian.
  2. Các trạng thái kề nhau theo quy tắc nào? 4 hướng, 8 hướng hay điều kiện riêng.
  3. Ô nào hợp lệ? Không vượt biên, không phải tường, thoả màu hoặc độ cao.
  4. Cần DFS hay BFS? Chỉ duyệt vùng thì dùng cách nào cũng được; cần đường ngắn nhất thì dùng BFS.
  5. Cần thu thập gì trong lúc loang? Số vùng, diện tích, chu vi, khoảng cách, đường đi hoặc nhãn thành phần.

Flood Fill là một trong những khuôn mẫu nền tảng nhất của lập trình thi đấu. Khi nhìn thấy ma trận và các vùng nối nhau, hãy nghĩ ngay đến việc biến mỗi ô thành một đỉnh và dùng DFS/BFS để duyệt thành phần liên thông.
