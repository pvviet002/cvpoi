TÌM KIẾM NHỊ PHÂN

Phan Văn Việt — Trường THPT Chuyên Vĩnh Phúc

Tìm kiếm nhị phân không chỉ dùng để tìm một giá trị trong mảng đã sắp xếp. Cốt lõi của kỹ thuật là nhận ra một miền có tính đơn điệu, kiểm tra điểm giữa rồi loại bỏ chắc chắn một nửa miền còn lại. Từ đó hình thành ba nhóm công cụ: tìm trên dãy tuyến tính, tìm biên bằng STL và tìm kiếm nhị phân trên đáp án.

Kiến thức nền
Mảng một chiều, sắp xếp, vòng lặp, hàm, iterator, kiểu long long, sai số số thực và đánh giá độ phức tạp.
Trọng tâm
Bất biến đoạn tìm kiếm, lower_bound, upper_bound, first true, last true, thiết kế hàm check và chống tràn số.

Nguồn nội dung: bộ lý thuyết và 10 bài thực hành tìm kiếm nhị phân do tác giả biên soạn; các bài 1–8 dựa trên lộ trình Binary Search của Codeforces EDU.

1.Từ tìm kiếm tuần tự đến tìm kiếm nhị phân trên dãy

Cho dãy đã sắp xếp tăng a = [2, 5, 8, 12, 16, 23, 38, 56, 72] và cần tìm giá trị x = 23. Tìm kiếm tuần tự kiểm tra từ trái sang phải, còn tìm kiếm nhị phân kiểm tra phần tử giữa rồi dùng thứ tự của dãy để loại bỏ một nửa.

TÌM KIẾM TUẦN TỰ

Không cần dãy được sắp xếp, nhưng trường hợp xấu nhất phải kiểm tra đủ n phần tử. Với nhiều truy vấn trên một dãy cố định, chi phí O(nq) có thể quá lớn.

TÌM KIẾM NHỊ PHÂN

Cần dãy được sắp xếp theo đúng quan hệ thứ tự đang dùng. Mỗi lần so sánh với phần tử giữa sẽ loại được khoảng một nửa đoạn, nên chỉ cần O(log n) bước.

Hình 1. Mỗi bước thu hẹp một nửa đoạn tìm kiếm

Đoạn còn xétPhần tử giữaKết quảPhần đã loại
ĐIỀU KIỆN TIÊN QUYẾT

Dãy phải được sắp xếp theo đúng comparator dùng khi tìm kiếm. Nếu dãy tăng thì dùng quan hệ mặc định; nếu dãy giảm bằng greater<int>(), thao tác tìm kiếm cũng phải dùng comparator tương ứng.

Khuôn tìm một phần tử bằng x

int binarySearch(const vector<int>& a, int x) {
    int left = 0;
    int right = (int)a.size() - 1;

    while (left <= right) {
        int mid = left + (right - left) / 2;

        if (a[mid] == x)
            return mid;

        if (a[mid] < x)
            left = mid + 1;
        else
            right = mid - 1;
    }

    return -1;
}

2.Vì sao thuật toán đúng và chạy nhanh

BẤT BIẾN ĐOẠN TÌM KIẾM

Ở đầu mỗi vòng lặp, nếu x có xuất hiện thì vẫn tồn tại ít nhất một vị trí chứa x trong đoạn đóng [left, right].

  1. Nếu a[mid] == x, ta đã tìm được một vị trí hợp lệ.
  2. Nếu a[mid] < x, do dãy tăng nên mọi phần tử từ left đến mid đều nhỏ hơn x. Cập nhật left = mid + 1.
  3. Nếu a[mid] > x, mọi phần tử từ mid đến right đều lớn hơn x. Cập nhật right = mid - 1.
  4. Khi left > right, đoạn rỗng; theo bất biến, x không xuất hiện.
ĐỘ PHỨC TẠP

Sau k bước, độ dài đoạn còn khoảng n/2k. Khi đoạn chỉ còn một phần tử, 2k ≥ n, nên k = O(log n).

TÍNH MID AN TOÀN

Dùng mid = left + (right - left) / 2 thay cho (left + right) / 2 để tránh tổng left + right vượt miền kiểu số.

VÍ DỤ: MUA NƯỚC NGỌT

Mảng x chứa giá bán và mỗi truy vấn cho số tiền m. Sau khi sắp xếp, số sản phẩm có giá không vượt m chính là vị trí phần tử đầu tiên lớn hơn m.

#include <bits/stdc++.h>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, q;
    cin >> n;
    vector<int> price(n);
    for (int& value : price)
        cin >> value;

    sort(price.begin(), price.end());

    cin >> q;
    while (q--) {
        int money;
        cin >> money;
        cout << upper_bound(price.begin(), price.end(), money)
                    - price.begin() << '\n';
    }
}
ĐỘ PHỨC TẠP CỦA BÀI NHIỀU TRUY VẤN

Sắp xếp một lần tốn O(n log n), mỗi truy vấn tốn O(log n). Tổng thời gian O(n log n + q log n), thay cho O(nq) nếu duyệt lại toàn bộ mảng.

6.Hai khuôn tổng quát: first true và last true

Nhiều bài không yêu cầu tìm một giá trị có sẵn trong mảng. Ta xét một mệnh đề check(x). Nếu kết quả của mệnh đề thay đổi đúng một lần trên miền tìm kiếm, ta có thể tìm biên chuyển trạng thái.

Hình 3. Hai dạng đơn điệu cơ bản

First true — giá trị nhỏ nhất thỏa

long long firstTrue(long long low, long long high) {
    while (low < high) {
        long long mid = low + (high - low) / 2;
        if (check(mid))
            high = mid;
        else
            low = mid + 1;
    }
    return low;
}

Dùng cho “thời gian nhỏ nhất”, “kích thước nhỏ nhất”, “chi phí nhỏ nhất”.

Last true — giá trị lớn nhất thỏa

long long lastTrue(long long low, long long high) {
    while (low < high) {
        long long mid = low + (high - low + 1) / 2;
        if (check(mid))
            low = mid;
        else
            high = mid - 1;
    }
    return low;
}

Dùng cho “độ dài lớn nhất”, “số sản phẩm tối đa”, “độ cao lớn nhất”.

VÌ SAO LAST TRUE DÙNG MID LỆCH PHẢI?

Nếu chỉ còn hai giá trị low và high = low + 1, phép chia lệch trái cho mid = low. Nếu check(mid) đúng và cập nhật low = mid, trạng thái không đổi và vòng lặp vô hạn. Thêm +1 trước khi chia 2 làm mid = high.

7.Tìm kiếm nhị phân trên đáp án nguyên

Quy trình thiết kế nên được thực hiện theo đúng thứ tự sau:

  1. Xác định đại lượng cần tối ưu và kiểu đáp án: nhỏ nhất hay lớn nhất.
  2. Chọn miền [LOW, HIGH] chắc chắn chứa đáp án.
  3. Viết check(mid): chỉ trả lời có thể đạt mục tiêu với giá trị mid hay không.
  4. Chứng minh check đơn điệu và xác định first true hay last true.
  5. Ước lượng O(log miền × chi phí check), kiểm tra tràn số và trường hợp biên.

Ví dụ 1 — cạnh hình vuông nhỏ nhất

Với hình vuông cạnh s, số hình chữ nhật w × h xếp được là ⌊s/w⌋·⌊s/h⌋. Khi tăng s, số hình xếp được không giảm, nên đây là first true.

long long w, h, n;

long long ceilDiv(long long a, long long b) {
    return a / b + (a % b != 0);
}

bool check(long long side) {
    long long rows = side / w;
    long long cols = side / h;
    if (rows == 0 || cols == 0) return false;

    // rows * cols >= n  <=>  cols >= ceil(n / rows)
    return cols >= ceilDiv(n, rows);
}

long long solve() {
    long long low = 0;
    long long high = 1;

    while (!check(high)) {
        if (high > LLONG_MAX / 2) {
            high = LLONG_MAX;
            break;
        }
        high *= 2;
    }
    if (!check(high)) return -1; // không có đáp án trong long long

    while (low < high) {
        long long mid = low + (high - low) / 2;
        if (check(mid)) high = mid;
        else low = mid + 1;
    }
    return low;
}

Ví dụ 2 — số hamburger tối đa

Giả sử mỗi bánh cần needB, needX, needP. Với cnt bánh, chỉ mua phần thiếu so với kho. Nếu làm được cnt bánh thì mọi số nhỏ hơn cũng làm được.

bool payIngredient(long long need, long long have, long long price,
                   long long cnt, long long &moneyLeft) {
    if (need == 0 || cnt <= have / need) return true;
    if (price == 0) return true;

    // Tách kho hiện có thành số bánh đủ nguyên liệu và phần dư.
    long long complete = have / need;
    long long remainder = have % need;
    long long batches = cnt - complete;       // batches >= 1
    long long firstMissing = need - remainder;

    // Chỉ cần biết số nguyên liệu tối đa còn mua được.
    long long maxCanBuy = moneyLeft / price;
    if (firstMissing > maxCanBuy) return false;

    long long afterFirst = maxCanBuy - firstMissing;
    if (batches - 1 > afterFirst / need) return false;

    // Đến đây tích bên dưới chắc chắn không vượt moneyLeft.
    long long missing = firstMissing + (batches - 1) * need;
    moneyLeft -= missing * price;
    return true;
}

bool canMake(long long cnt) {
    long long moneyLeft = money;
    return payIngredient(needB, haveB, priceB, cnt, moneyLeft)
        && payIngredient(needX, haveX, priceX, cnt, moneyLeft)
        && payIngredient(needP, haveP, priceP, cnt, moneyLeft);
}

THIẾT KẾ CHECK HIỆU QUẢ
  • Không cần tính chính xác sau khi đã biết kết quả; có thể dừng sớm khi tổng đã đạt ngưỡng.
  • Tránh tạo tích lớn: đổi phép so sánh tích thành phép chia, kiểm tra a > limit / b trước khi nhân hoặc dừng sớm khi tổng đã đạt ngưỡng.
  • Không thay đổi dữ liệu gốc theo cách khiến lần gọi check sau phụ thuộc lần trước.
  • Nếu chưa biết cận trên, có thể bắt đầu từ 1 và nhân đôi đến khi gặp trạng thái chắc chắn thỏa.

8.Tìm kiếm nhị phân trên số thực

Với số thực, không có bước “cộng 1” hay “trừ 1”. Ta thu hẹp đoạn bằng cách gán một đầu bằng mid. Trong thi đấu, lặp cố định 80–100 lần thường dễ kiểm soát hơn điều kiện dừng bằng epsilon.

double left = LOW;
double right = HIGH;

for (int step = 0; step < 100; ++step) {
    double mid = (left + right) / 2.0;
    if (check(mid))
        left = mid;      // đang tìm giá trị lớn nhất thỏa
    else
        right = mid;
}

cout << fixed << setprecision(10) << left;
CẮT DÂY

Với độ dài đoạn len, số đoạn cắt được là Σ⌊ai/len⌋. Độ dài càng lớn thì số đoạn không tăng. Tìm độ dài lớn nhất vẫn cắt được ít nhất k đoạn.

PHƯƠNG TRÌNH x² + √x = c

Hàm f(x)=x²+√x tăng trên x ≥ 0. Nếu f(mid) < c thì nghiệm ở bên phải; ngược lại nghiệm ở bên trái.

PHƯƠNG TRÌNH BẬC BA KHÔNG ĐƠN ĐIỆU TRÊN TOÀN ĐOẠN

Không được nhị phân trực tiếp trên [-100, 100] chỉ dựa vào dấu của đa thức, vì hàm bậc ba có thể đổi chiều. Với giả thiết ba nghiệm phân biệt cách nhau ít nhất 1, có thể quét các đoạn đơn vị để tìm đoạn đổi dấu, rồi nhị phân riêng từng đoạn chứa nghiệm.

double f(double x) {
    return ((a * x + b) * x + c) * x + d;
}

vector<double> roots;
for (int integer = -100; integer < 100; ++integer) {
    double left = integer;
    double right = integer + 1;
    if (fabs(f(left)) < 1e-10) {
        roots.push_back(left);
        continue;
    }
    if (f(left) * f(right) > 0) continue;

    for (int step = 0; step < 100; ++step) {
        double mid = (left + right) / 2;
        if (f(left) * f(mid) <= 0) right = mid;
        else left = mid;
    }
    roots.push_back((left + right) / 2);
}

BẪY 1 — “CÓ HÀM CHECK LÀ NHỊ PHÂN ĐƯỢC”

Nhận định sai: chỉ cần viết được một hàm kiểm tra là có thể chặt đôi miền đáp án.

Lý do sai: nếu dãy kết quả của check đổi đúng–sai nhiều lần, quyết định bỏ một nửa không còn an toàn.

Cách phòng tránh: chứng minh rõ dạng false…false true…true hoặc true…true false…false trước khi viết vòng lặp.

BẪY 2 — NHẦM LOWER_BOUND VÀ UPPER_BOUND

Nhận định sai: upper_bound(x) trả về phần tử cuối cùng bằng x.

Lý do sai: hàm trả về phần tử đầu tiên lớn hơn x; phần tử cuối cùng ≤ x nằm ngay trước iterator đó.

Cách phòng tránh: ghi nhớ: lower = đầu tiên ≥; upper = đầu tiên >.

BẪY 3 — VÒNG LẶP VÔ HẠN

Nhận định sai: dùng mid = (left + right) / 2 và left = mid luôn làm đoạn nhỏ đi.

Lý do sai: khi right = left + 1, mid bằng left.

Cách phòng tránh: last true phải tính mid lệch phải hoặc dùng khuôn lính canh đã kiểm chứng.

BẪY 4 — TRÀN SỐ TRONG CHECK

Nhận định sai: các biến đầu vào vừa long long thì mọi phép nhân của chúng cũng vừa.

Lý do sai: tích trung gian có thể vượt 9·1018 dù kết quả cuối chỉ cần so với một ngưỡng nhỏ hơn.

Cách phòng tránh: biến phép nhân thành phép chia an toàn, kiểm tra trước bằng a > limit / b, giới hạn tổng ở ngưỡng cần so sánh hoặc dừng sớm khi đã đủ kết luận.

BẪY 5 — TRUY CẬP ITERATOR KHÔNG HỢP LỆ

Nhận định sai: kết quả STL luôn trỏ vào một phần tử của mảng.

Lý do sai: có thể nhận end(); phép lùi từ begin() cũng không hợp lệ.

Cách phòng tránh: kiểm tra biên iterator trước khi lấy giá trị hoặc lùi một bước.

BẪY 6 — CẬN ĐÁP ÁN KHÔNG BAO PHỦ NGHIỆM

Nhận định sai: chọn một cận phải “có vẻ đủ lớn” mà không chứng minh.

Lý do sai: thuật toán chỉ tìm trong miền được cấp; nghiệm nằm ngoài miền sẽ không bao giờ xuất hiện.

Cách phòng tránh: suy ra cận từ ràng buộc hoặc nhân đôi cận đến khi đạt trạng thái chắc chắn.

TỰ KIỂM TRƯỚC KHI NỘP
  • Dãy đã được sắp xếp và comparator tìm kiếm khớp với comparator sắp xếp.
  • Đã xác định chính xác đoạn đóng hay nửa mở.
  • Đã thử các trường hợp dãy rỗng, một phần tử, không có đáp án và mọi phần tử đều bằng nhau.
  • Đã chứng minh tính đơn điệu của check.
  • Đã kiểm tra cận trái, cận phải và phép nhân trung gian.
  • Với số thực, đã in đủ độ chính xác và kiểm tra hàm đơn điệu trên từng đoạn.
