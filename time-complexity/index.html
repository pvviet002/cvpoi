Độ phức tạp thời gian

Phan Văn Việt — Trường THPT Chuyên Vĩnh Phúc

Độ phức tạp thời gian ước lượng số phép toán một thuật toán phải làm, viết thành một hàm theo kích thước dữ liệu n. Nhờ nó, ta biết thuật toán có đủ nhanh hay không trước khi ngồi cài đặt — và loại sớm những hướng chắc chắn quá chậm.

Ký hiệu O-lớn
Ta viết độ phức tạp dưới dạng O(f(n)): chỉ giữ bậc lớn nhất, bỏ hằng số nhân và các số hạng nhỏ. Ví dụ một vòng lặp chạy 3n + 5 lần vẫn là O(n).

1.Đọc độ phức tạp từ đoạn mã

Vòng lặp. Mỗi vòng lặp duyệt hết dữ liệu tốn O(n). Càng lồng nhiều vòng, bậc càng cao: k vòng lồng nhau cho O(nk).

for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++)
        // ... O(n^2)

Các giai đoạn nối tiếp. Nếu thuật toán gồm nhiều đoạn chạy lần lượt, độ phức tạp tổng bằng đoạn chậm nhất: O(n) + O(n2) + O(n) = O(n2).

Đệ quy. Chi phí bằng số lần gọi nhân với chi phí mỗi lần. Hàm gọi lại chính nó hai lần với n−1 tạo ra 1 + 2 + 4 + … lần gọi:

void g(int n) {
    if (n == 1) return;
    g(n - 1);
    g(n - 1);   // 2^n - 1 lần gọi  ->  O(2^n)
}

3.Đoán độ phức tạp cần thiết

Một máy tính hiện nay làm được cỡ vài trăm triệu phép toán mỗi giây. Từ kích thước dữ liệu, ta đoán ngược ra độ phức tạp mà thuật toán phải đạt để kịp trong một giây:

Kích thước dữ liệuĐộ phức tạp cần đạt
n ≤ 10O(n!)
n ≤ 20O(2ⁿ)
n ≤ 500O(n³)
n ≤ 5000O(n²)
n ≤ 10⁶O(n log n) hoặc O(n)
n rất lớnO(1) hoặc O(log n)

4.Ví dụ: đoạn con có tổng lớn nhất

Cho một dãy n số (có thể âm), hãy tìm một đoạn liên tiếp có tổng lớn nhất. Cho phép đoạn rỗng nên đáp số luôn không âm. Ví dụ với dãy dưới đây, đoạn tô đậm [2, 4, −3, 5, 2] có tổng lớn nhất bằng 10.

Bài này có ba cách với độ phức tạp giảm dần. Cách 1 — xét mọi đoạn [i, j] rồi cộng lại, ba vòng lồng nhau, O(n³):

int best = 0;
for (int i = 0; i < n; i++)
    for (int j = i; j < n; j++) {
        int sum = 0;
        for (int k = i; k <= j; k++) sum += a[k];
        best = max(best, sum);
    }
cout << best << "\n";

Cách 2 — vừa dịch đầu cuối vừa cộng dồn, bỏ được một vòng, O(n²):

int best = 0;
for (int i = 0; i < n; i++) {
    int sum = 0;
    for (int j = i; j < n; j++) {
        sum += a[j];
        best = max(best, sum);
    }
}
cout << best << "\n";

Cách 3 (thuật toán Kadane) — với mỗi vị trí, tính tổng đoạn tốt nhất kết thúc tại đó. Nếu tổng đang có mà cộng thêm phần tử mới lại nhỏ hơn chính phần tử đó, ta bỏ đoạn cũ, bắt đầu đoạn mới. Chỉ một vòng lặp, O(n):

int best = 0, sum = 0;
for (int k = 0; k < n; k++) {
    sum = max(a[k], sum + a[k]);
    best = max(best, sum);
}
cout << best << "\n";

Bấm Chạy Kadane rồi đi từng bước để thấy sum (tổng đoạn đang xét) và best (tốt nhất tới giờ) thay đổi thế nào. Đoạn tốt nhất được tô xanh lá.

Vì sao O(n³) “bùng nổ”?

Ba cách cho cùng đáp số, nhưng số phép toán chênh nhau rất xa khi n lớn. Kéo thanh dưới đây để so sánh (số phép toán là chính xác, không phụ thuộc máy):

So sánh số phép toán theo n

Ở mốc một giây (~10⁸–10⁹ phép toán), cách O(n³) đuối ngay khi n ≈ 104, cách O(n²) đuối quanh n ≈ 105, còn Kadane xử lý được cả dãy rất lớn mà không đáng kể.
