1.Tạo vấn đề: một phép trừ tưởng đúng

Xét các chuỗi độ dài 4 tạo từ ba ký hiệu A, B, C. Cần đếm số chuỗi trong đó cả ba ký hiệu đều xuất hiện ít nhất một lần.

CÁCH NGHĨ CHƯA ĐỦ

Có tất cả 34 = 81 chuỗi. Với mỗi ký hiệu bị thiếu, còn 24 chuỗi chỉ dùng hai ký hiệu còn lại. Trừ 3 × 24 cho kết quả 33.

Phép trừ này làm các chuỗi chỉ dùng đúng một ký hiệu bị trừ hai lần. Ví dụ chuỗi AAAA vừa nằm trong nhóm “thiếu B”, vừa nằm trong nhóm “thiếu C”.

CÁCH NGHĨ ĐÚNG

Sau khi trừ các nhóm thiếu một ký hiệu, phải cộng lại phần giao của từng cặp nhóm. Có 3 cách chọn hai ký hiệu bị thiếu và mỗi cách còn đúng 1 chuỗi.

Kết quả là 81 − 48 + 3 = 36.

CÂU HỎI CHUYỂN TIẾP

Vì sao chuỗi bị trừ hai lần phải được cộng lại đúng một lần, và khi có nhiều điều kiện hơn thì dấu cộng, trừ phải sắp xếp thế nào?

2.Vì sao nguyên lý bù trừ là đúng

Nguyên lý bù trừ đếm hợp của nhiều tập bằng cách cộng số phần tử của từng tập, trừ các giao đôi, cộng các giao ba và tiếp tục đổi dấu. Trong bài toán chuỗi, tập Mi gồm các chuỗi không dùng ký hiệu thứ i.

Số chuỗi hợp lệ = ∑i=0k (−1)i × C(k, i) × (k − i)n

Chọn i ký hiệu bị cấm có C(k, i) cách. Sau khi cấm, mỗi vị trí của chuỗi còn k − i lựa chọn, nên có (k − i)n chuỗi. Dấu của hạng tử đổi theo tính chẵn lẻ của i.

CHỨNG MINH BẰNG HỆ SỐ CỦA MỘT ĐỐI TƯỢNG

Xét một chuỗi cụ thể đang thiếu đúng m ký hiệu. Khi cộng trừ tất cả các tập, chuỗi này được tính với tổng hệ số:

C(m, 1) − C(m, 2) + C(m, 3) − … + (−1)m+1C(m, m) = 1

Đẳng thức trên suy ra từ (1 − 1)m = 0. Vì vậy mỗi chuỗi không hợp lệ xuất hiện đúng một lần trong hợp các tập bị cấm. Chuỗi hợp lệ không thuộc tập nào nên có hệ số 0 trong phần bị loại. Lấy tổng tất cả chuỗi rồi trừ hợp các chuỗi không hợp lệ là an toàn.

Hình 1. Vì sao chia cho r! khi chuyển từ chỉnh hợp sang tổ hợp

Chỉnh hợp đếm cả thứ tự. Tổ hợp gộp r! thứ tự của cùng một tập thành một lựa chọn, nên C(n, r) = P(n, r) / r!.

Mỗi bước xử lý một giá trị i: số ký hiệu bị cấm. Màu xanh lá là hạng cộng, màu đỏ là hạng trừ, màu xanh dương là hạng đang xét.

BẪY KIỂU DỮ LIỆU VÀ SỐ DƯ
  • Dùng long long cho tích hai số dư. Khuôn trong trang giả sử MOD đủ nhỏ để tích không vượt giới hạn của long long.
  • Sau phép trừ, chuẩn hóa bằng (x - y + MOD) % MOD hoặc cộng MOD trước khi lấy số dư.
  • Không dùng kiểu long để thay cho long long trên MinGW 32-bit.
BIÊN VÀ CHỈ SỐ
  • Quy ước C(n, r) = 0 khi r < 0 hoặc r > n.
  • Tiền xử lý mảng từ 0 đến N; luôn đặt 0! = 1.
  • Hàm lũy thừa nhanh thường trả 1 cho a0, kể cả khi a = 0. Cần đối chiếu ý nghĩa tổ hợp của trường hợp n = 0.
  • Khi dùng vòng lặp giảm với biến không dấu, điều kiện dừng dễ bị tràn vòng. Khuôn dưới đây dùng int cho chỉ số.

4.Khuôn mẫu cài đặt

Khuôn A — giai thừa và nghịch đảo giai thừa, MOD nguyên tố

Giữ nguyên hàm lũy thừa, phần tiền xử lý và hàm C(n, r). Chỉ thay giới hạn N, mô-đun và phần công thức của bài.

#include <bits/stdc++.h>
using namespace std;

const long long MOD = 1000000007LL;
vector<long long> fact, invFact;

long long modPow(long long a, long long e) {
    long long res = 1;
    while (e > 0) {
        if (e & 1)
            res = res * a % MOD;
        a = a * a % MOD;
        e >>= 1;
    }
    return res;
}

void prepareComb(int n) {
    fact.assign(n + 1, 1);
    invFact.assign(n + 1, 1);
    for (int i = 1; i <= n; ++i)
        fact[i] = fact[i - 1] * i % MOD;

    invFact[n] = modPow(fact[n], MOD - 2);
    for (int i = n; i >= 1; --i)
        invFact[i - 1] = invFact[i] * i % MOD;
}

long long comb(int n, int r) {
    if (r < 0 || r > n)
        return 0;
    return fact[n] * invFact[r] % MOD * invFact[n - r] % MOD;
}

Hình 2. Tiền xử lý một lần, trả lời nhiều truy vấn

Mảng fact đi xuôi. Chỉ cần tính một nghịch đảo ở cuối, sau đó suy ra toàn bộ invFact khi đi ngược.

Giai thừaNghịch đảo giai thừaGiá trị được dùng trong truy vấn

Khuôn B — tam giác Pascal, không cần phép chia

Khuôn này phù hợp khi n nhỏ, mô-đun không nguyên tố hoặc cần toàn bộ C(n, r) trong một vùng nhỏ.

vector<vector<long long>> buildPascal(int n, long long mod) {
    vector<vector<long long>> c(n + 1, vector<long long>(n + 1, 0));
    c[0][0] = 1;
    for (int i = 1; i <= n; ++i) {
        c[i][0] = c[i][i] = 1;
        for (int j = 1; j < i; ++j)
            c[i][j] = (c[i - 1][j - 1] + c[i - 1][j]) % mod;
    }
    return c;
}

Chương trình hoàn chỉnh — đếm chuỗi dùng đủ mọi ký hiệu

Đầu vào gồm độ dài n và số ký hiệu k. Chương trình tính số chuỗi độ dài n dùng đủ cả k ký hiệu theo mô-đun 1 000 000 007. Khuôn giả sử k nhỏ hơn MOD và đủ nhỏ để tiền xử lý mảng.

#include <bits/stdc++.h>
using namespace std;

const long long MOD = 1000000007LL;
vector<long long> fact, invFact;

long long modPow(long long a, long long e) {
    long long res = 1;
    a %= MOD;
    while (e > 0) {
        if (e & 1)
            res = res * a % MOD;
        a = a * a % MOD;
        e >>= 1;
    }
    return res;
}

void prepareComb(int n) {
    fact.assign(n + 1, 1);
    invFact.assign(n + 1, 1);
    for (int i = 1; i <= n; ++i)
        fact[i] = fact[i - 1] * i % MOD;

    invFact[n] = modPow(fact[n], MOD - 2);
    for (int i = n; i >= 1; --i)
        invFact[i - 1] = invFact[i] * i % MOD;
}

long long comb(int n, int r) {
    if (r < 0 || r > n)
        return 0;
    return fact[n] * invFact[r] % MOD * invFact[n - r] % MOD;
}

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(NULL);

    long long n;
    int k;
    if (!(cin >> n >> k))
        return 0;

    prepareComb(k);

    long long ans = 0;
    for (int i = 0; i <= k; ++i) {
        long long waysChooseMissing = comb(k, i);
        long long waysFill = modPow(k - i, n);
        long long term = waysChooseMissing * waysFill % MOD;

        if (i & 1)
            ans = (ans - term + MOD) % MOD;
        else
            ans = (ans + term) % MOD;
    }

    cout << ans << '\n';
    return 0;
}
ĐỘ PHỨC TẠP

Tiền xử lý tổ hợp tốn O(k + log MOD). Vòng bù trừ có k + 1 hạng, mỗi hạng tính một lũy thừa nhanh O(log n), nên tổng là O(k log n). Bộ nhớ O(k).

PHÂN LOẠI MỨC THAY ĐỔI

Sửa nhỏ thay điều kiện chọn r, đổi số loại hoặc ghép thêm một hệ số tổ hợp.

BẪY 1 — CHIA TRỰC TIẾP SAU KHI LẤY MOD

Nhận định sai: Tính n! mod MOD rồi chia cho r! mod MOD.

Lý do sai: Phép chia số nguyên không bảo toàn quan hệ đồng dư.

Phòng tránh: Nhân với nghịch đảo mô-đun khi điều kiện tồn tại được bảo đảm.

BẪY 2 — CHỈ TRỪ CÁC ĐIỀU KIỆN XẤU

Nhận định sai: Mỗi điều kiện xấu trừ một lần là đủ.

Lý do sai: Một cấu hình có thể vi phạm nhiều điều kiện và bị trừ lặp.

Phòng tránh: Vẽ quan hệ giao hoặc xét hệ số của một cấu hình cụ thể.

BẪY 3 — DÙNG KHUÔN GIAI THỪA KHI n ≥ MOD

Nhận định sai: Chỉ cần tăng kích thước mảng.

Lý do sai: Giai thừa chứa thừa số MOD nên bằng 0 theo mô-đun.

Phòng tránh: Kiểm tra giới hạn trước khi chọn Lucas, CRT hoặc phương pháp khác.

BẪY 4 — QUÊN PHÂN BIỆT VẬT VÀ HỘP

Nhận định sai: Mọi bài phân phối đều dùng C(n + k − 1, k − 1).

Lý do sai: Công thức đó dành cho vật giống nhau và hộp phân biệt, không có giới hạn trên.

Phòng tránh: Ghi rõ vật có phân biệt, hộp có phân biệt và mỗi hộp được nhận bao nhiêu.

TỰ KIỂM TRƯỚC KHI NỘP
  • Tôi đã xác định rõ thứ tự có quan trọng hay không.
  • Tôi đã ghi rõ vật và hộp có phân biệt hay không.
  • Tôi đã kiểm tra các tập điều kiện xấu có giao nhau không.
  • Tôi đã xác nhận MOD nguyên tố trước khi dùng Fermat nhỏ.
  • Tôi đã kiểm tra giới hạn lớn nhất có nhỏ hơn MOD hay không.
  • Tôi đã chuẩn hóa số âm sau phép trừ theo mô-đun.
  • Tôi đã thử các biên n = 0, k = 0, r = 0 và r > n khi chúng hợp lệ với đề.
  • Tôi đã so sánh với vét cạn cho dữ liệu nhỏ.
