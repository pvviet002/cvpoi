QUY HOẠCH ĐỘNG CHỮ SỐ

Phan Văn Việt — Trường THPT Chuyên Vĩnh Phúc

Quy hoạch động chữ số đếm hoặc tối ưu trên một đoạn số rất lớn bằng cách dựng số từ trái sang phải. Mỗi trạng thái chỉ giữ những thông tin của tiền tố có ảnh hưởng tới các chữ số còn lại: vị trí hiện tại, quan hệ với cận, trạng thái bắt đầu số và các đại lượng mà đề yêu cầu theo dõi.

Kiến thức nền
Quy hoạch động có nhớ, đệ quy, biểu diễn thập phân, số dư, phép đếm, độ phức tạp và kiểu long long.
Trọng tâm
Hàm đếm từ 0 đến X, trạng thái tight, chữ số 0 ở đầu, thiết kế trạng thái phụ và chuyển đáp án từ đoạn [L, R].

Nguồn bài luyện: danh sách cuối bài viết Digit DP của flash_7 trên Codeforces. Trang này viết lại mạch lý thuyết bằng tiếng Việt, bổ sung xử lý số 0 ở đầu và sắp xếp bài luyện theo mức độ.

1.Tạo vấn đề: duyệt từng số không còn khả thi

Cần đếm các số nguyên trong đoạn từ 0 đến 325 mà chữ số 2 xuất hiện đúng một lần. Duyệt lần lượt 326 số cho kết quả 124, nhưng cách đó trở nên vô dụng khi cận phải gần 1018 hoặc được cho bằng một chuỗi hàng trăm chữ số.

CÁCH NGHĨ CHƯA ĐỦ

Dựng mọi dãy ba chữ số từ 000 đến 999 rồi kiểm tra dãy nào không vượt 325. Cách này vẫn sinh quá nhiều nhánh: phần lớn dãy bắt đầu bằng 4, 5, 6, 7, 8 hoặc 9 chắc chắn không hợp lệ nhưng chỉ bị loại sau khi đã dựng.

CÁCH NGHĨ ĐÚNG

Dựng từ trái sang phải và so tiền tố với 325. Nếu tiền tố đã nhỏ hơn tiền tố tương ứng của 325, mọi chữ số sau đều được chọn từ 0 đến 9. Nếu tiền tố còn bằng cận, chữ số tiếp theo không được vượt chữ số của cận tại vị trí đó.

Hàm chuẩn thường có dạng dp(pos, tight, started, state). Bốn thành phần này trả lời đúng bốn câu hỏi mà phần đuôi cần biết.

Xét hai tiền tố có cùng pos, cùng tight, cùng started và cùng trạng thái phụ. Mọi lựa chọn hợp lệ cho chữ số tiếp theo của tiền tố thứ nhất cũng hợp lệ cho tiền tố thứ hai, đồng thời tạo ra cùng trạng thái mới. Do đó số cách hoàn thiện phần đuôi của hai tiền tố bằng nhau.

Đây là lý do có thể bỏ toàn bộ giá trị tiền tố khỏi khóa ghi nhớ. Tiền tố chỉ cần để lại những đặc trưng có ảnh hưởng tới tương lai.

Đặt F(X) là số lượng số hợp lệ trong đoạn từ 0 đến X. Khi đó đáp án trên đoạn [L, R] là:

Answer(L, R) = F(R) − F(L − 1)

Cách tách này loại bỏ nhu cầu theo dõi đồng thời cận dưới và cận trên trong hầu hết bài cơ bản.

Khi chọn chữ số 0 trong lúc started = 0, không tăng bộ đếm chữ số 0, không cập nhật chữ số trước và không đưa 0 vào mặt nạ chữ số đã dùng. Chỉ khi số đã bắt đầu hoặc chữ số đang chọn khác 0 thì chữ số mới thuộc biểu diễn thật.

KIỂU DỮ LIỆU, CHỈ SỐ VÀ ĐIỀU KIỆN DỪNG
  • Cận đến 1018 có tối đa 19 chữ số, nhưng số lượng trạng thái phụ có thể lớn hơn nhiều nếu theo dõi số dư hoặc mặt nạ.
  • Dùng long long tường minh; kiểu long chỉ có 4 byte trên MinGW 32-bit.
  • Ở điều kiện dừng pos == s.size(), chỉ kiểm tra thuộc tính cuối cùng; không sinh thêm chữ số.
  • Trạng thái phụ phải có miền giá trị hữu hạn. Không lưu nguyên tổng hoặc tích nếu nó có thể tăng quá lớn mà đề chỉ cần số dư, dấu hoặc so sánh ngưỡng.

4.Khuôn mẫu cài đặt

Khuôn A — hàm đếm từ 0 đến X

Phần giữ nguyên gồm việc chuyển cận thành chuỗi, duyệt vị trí từ trái sang phải, xác định chữ số tối đa bằng tight và ghi nhớ trạng thái. Phần thay đổi là trạng thái phụ, cách cập nhật trạng thái phụ và điều kiện nhận ở cuối.

long long dp(int pos, bool tight, bool started, int state) {
    if (pos == (int)s.size())
        return ok(started, state);             // trạng thái cuối có hợp lệ?

    if (vs[pos][tight][started][state])
        return memo[pos][tight][started][state];

    vs[pos][tight][started][state] = true;
    long long res = 0;
    int hi = tight ? s[pos] - '0' : 9;         // chữ số lớn nhất được phép

    for (int c = 0; c <= hi; c++) {
        bool nt = tight && c == hi;             // bước sau còn bám cận?
        bool ns = started || c != 0;           // số đã bắt đầu?
        int st = trans(state, c, started, ns); // chuyển trạng thái phụ
        if (st == BAD) continue;               // chuyển không hợp lệ thì bỏ
        res += dp(pos + 1, nt, ns, st);
    }

    return memo[pos][tight][started][state] = res;
}
CHI TIẾT VỀ nt

hi là chữ số lớn nhất được phép: bằng chữ số của cận khi tight = 1, bằng 9 khi tiền tố đã nhỏ hơn cận. Nhờ vậy nt = tight && c == hi đọc thẳng ra ý: chỉ khi đang bám cận mà lại chọn đúng chữ số lớn nhất thì bước sau mới còn bám cận; đã nhỏ hơn cận rồi thì nt luôn bằng 0.

Chương trình hoàn chỉnh — đếm chữ số d xuất hiện đúng k lần

Đầu vào gồm L, R, d, k, với 0 ≤ L ≤ R ≤ 1018. Chương trình quy ước biểu diễn thập phân của số 0 là chuỗi “0”.

#include <bits/stdc++.h>
using namespace std;

string s;                            // các chữ số của cận
int d, k;                            // đếm chữ số d xuất hiện đúng k lần
long long memo[20][2][2][20];
bool vs[20][2][2][20];

long long dp(int pos, bool tight, bool started, int cnt) {
    if (pos == (int)s.size()) {
        if (!started && d == 0) cnt = 1;       // số 0 gồm đúng một chữ số 0
        return cnt == k;
    }
    if (vs[pos][tight][started][cnt])
        return memo[pos][tight][started][cnt];
    vs[pos][tight][started][cnt] = true;

    long long res = 0;
    int hi = tight ? s[pos] - '0' : 9;         // chữ số lớn nhất được phép
    for (int c = 0; c <= hi; c++) {
        bool nt = tight && c == hi;             // bước sau còn bám cận?
        bool ns = started || c != 0;           // số đã bắt đầu?
        int nc = cnt + (ns && c == d);         // gặp chữ số d thì tăng đếm
        if (nc > k) continue;                  // vượt k lần thì bỏ nhánh
        res += dp(pos + 1, nt, ns, nc);
    }
    return memo[pos][tight][started][cnt] = res;
}

long long F(long long x) {                     // đếm số hợp lệ trong [0, x]
    if (x < 0) return 0;
    s = to_string(x);
    memset(vs, 0, sizeof(vs));
    return dp(0, true, false, 0);
}

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(NULL);
    long long L, R;
    cin >> L >> R >> d >> k;
    cout << F(R) - F(L - 1) << '\n';
    return 0;
}
DỮ LIỆU KIỂM NHANH
Input

Output
124
ĐỘ PHỨC TẠP

Với D chữ số và bộ đếm từ 0 đến k, số trạng thái là O(Dk) và mỗi trạng thái thử tối đa 10 chữ số. Thời gian là O(10Dk), bộ nhớ là O(Dk). Hai chiều Boolean chỉ tạo hệ số hằng.

BẪY 1 — “DÃY 0007 CÓ BA CHỮ SỐ 0”

Nhận định sai: mọi vị trí đã điền đều là chữ số thật của số.

Lý do sai: các số 0 trước chữ số 7 chỉ dùng để mọi số có cùng độ dài với cận.

Cách phòng tránh: thêm started và chỉ cập nhật thuộc tính chữ số khi số đã bắt đầu.

BẪY 2 — “TIGHT CHỈ PHỤ THUỘC CHỮ SỐ HIỆN TẠI”

Nhận định sai: cứ chọn chữ số không vượt chữ số cận tại vị trí hiện tại là đủ.

Lý do sai: nếu tiền tố đã nhỏ hơn cận, chữ số hiện tại có thể lớn hơn chữ số cận cùng vị trí mà toàn số vẫn nhỏ hơn cận.

Cách phòng tránh: giới hạn bằng 9 khi tight = 0; chỉ bám chữ số cận khi tight = 1.

BẪY 3 — “CỨ THÊM TRẠNG THÁI LÀ ĐƯỢC”

Nhận định sai: thêm tổng, số dư, mặt nạ và chữ số trước vào cùng một DP luôn chạy được.

Lý do sai: tích kích thước các chiều có thể vượt giới hạn thời gian và bộ nhớ.

Cách phòng tránh: tính số trạng thái trước khi viết mã, loại chiều suy ra được và tìm cách nén thuộc tính theo số dư, mặt nạ hoặc ngưỡng.

BẪY 4 — “F(R) − F(L − 1) LUÔN AN TOÀN”

Nhận định sai: không cần xử lý riêng khi L bằng 0.

Lý do sai: L − 1 âm và không có biểu diễn chữ số theo khuôn thông thường.

Cách phòng tránh: cho F(X) trả 0 ngay khi X < 0.

7.Lộ trình bài luyện

Các bài dưới đây đều xuất hiện trong danh sách bài luyện của bài viết Codeforces đã nêu, xếp theo mức độ tăng dần. Mỗi liên kết dẫn thẳng tới hệ thống chấm gốc; cột đọc lại mục chỉ ra phần lý thuyết cần xem trước khi bắt tay.

  2. Digit Sum — tổng chữ số với nhiều bộ dữ liệu. Đọc lại mục 3, 4.
  3. Investigation — theo dõi đồng thời số dư của số và tổng chữ số. Đọc lại mục 4, 5.

TỰ KIỂM TRƯỚC KHI NỘP
  • Đã định nghĩa chính xác F(X) có bao gồm số 0 hay không.
  • Đã phân biệt số 0 ở đầu với chữ số 0 thật bằng started hoặc một lập luận tương đương.
  • Đã tính trước tổng số trạng thái và số chuyển để chắc chắn không vượt giới hạn.
  • Đã kiểm tra L = 0, L = R, cận chỉ có một chữ số và thuộc tính không thể đạt.
  • Đã xóa bộ nhớ ghi nhớ khi đổi cận hoặc tách trạng thái bám cận khỏi phần tái sử dụng.
  • Đã so kết quả DP với vét cạn trên các cận nhỏ trước khi nộp.
